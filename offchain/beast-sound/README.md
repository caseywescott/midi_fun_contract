# @koji/beast-sound

Every Loot Survivor Beast has a theme, and its history arranges it. This package composes that
theme **entirely offchain**, from Beast data that already exists. No Sound contract, no new
storage, and nothing for Provable Games to deploy.

```
Beast traits ─┐   (V3 token ID, or get_beast on the current collection)
              ├─► composeBeast() ─► notes · MIDI file · BSN1 · score hash
Live stats ───┘   (kills, Summit deaths, hours on the Summit, species rank)
```

The engine is a port of the Cairo reference in `src/composition/beast_v3_sound.cairo`. For the same
inputs it gives the same score hash, the same notes, and byte-identical MIDI. The tests check this
against fixtures generated by the Cairo code, so anyone can verify the music without trusting this
package. If an onchain Sound contract is ever wanted, the Cairo reference is ready and both produce
the same music.

## Use

```js
import { composeBeast, genesisBeast, decodeTokenId } from '@koji/beast-sound';
import { readMainnetBeast, readV3Beast } from '@koji/beast-sound/chain';

// From chain (public reads only)
const { beast, live } = await readMainnetBeast(52918);       // Sorrow Peak Warlock
const song = composeBeast(beast, live);
song.midi        // Uint8Array, Standard MIDI File
song.events      // [{ time, duration, pitch, velocity, voice, section, role }]
song.scoreHash   // commitment to the whole performance

// Without any chain access
const warlock = genesisBeast({ id: 1, prefix: 57, suffix: 15, level: 126, health: 229 });
composeBeast(warlock, { adventurers_killed: 2, scars: 12, rank: 1, species_count: 954 });

// Beasts V3: every static trait is in the token ID
composeBeast(decodeTokenId(0x2e0064000a081000000000000004cn), { rank: 1, species_count: 1 });
```

CLI:

```bash
npx beast-sound mainnet 52918 -o warlock.mid
npx beast-sound v3 0x2e0064000a081000000000000004c          # Beasts V3 on Sepolia
npx beast-sound compose --species 29 --prefix 20 --suffix 5 --level 150 --kills 9 -o dragon.mid
```

## What the music reads

| Input | Where it comes from today | Musical effect |
|---|---|---|
| species, prefix, suffix | token | seed: the Beast's fixed melody (never changes) |
| type × tier | token | canon family, voice budget, section-B key relation |
| prefix / suffix | token | key and mode / ornament policy |
| level, health | token | extra voice at level ≥ 64; heavier register at health ≥ 250 |
| shiny, animated | token | tempo, articulation, velocity ceiling |
| adventurers killed | Beasts NFT `get_adventurers_killed` | sections (A → A–E), stretto, ornament |
| Summit deaths | Summit `get_live_stats` → `revival_count` | scars: 7+ invert the follower voice |
| hours on the Summit | Summit `get_live_stats` → `summit_held_seconds` | 16+ h adds ornament |
| species rank | Beasts NFT `get_beast_rank`, `get_species_count` | crown (rank 1), extra voice in top 1% |

## Sound rarity drop, no contract

```js
import { dropSaltFromBlockHash, hasSound } from '@koji/beast-sound';
const salt = dropSaltFromBlockHash(blockHashOfAnnouncedBlock); // announce block N before launch
hasSound(beast, { salt, bps: 500 });                           // 5%; Genesis Beasts always sing
```

The salt is unknown until block N exists and checkable by anyone afterwards. The result depends
only on species, prefix, suffix and the salt, so it survives the V2 → V3 `burn_and_mint`.

## Versioning

`ENGINE_VERSION` is 1. A Beast's music must never change silently: any change to the output is a
new major version, and old versions stay installable so earlier renders stay reproducible. The
golden fixtures in `test/golden.json` are the contract.

## Verify against Cairo

```bash
npm test                                            # offchain only, uses test/golden.json
# from midi_fun_contract/, to regenerate fixtures from the Cairo reference:
scarb test -- --include-ignored --filter beast_v3_parity_fixture | grep PARITY > /tmp/parity.txt
node scripts/beast_v3_parity.mjs /tmp/parity.txt --write
```

## Engine v2 (preview): ornamented invertible canon

```js
const song = composeBeast(beast, live, { engineVersion: 2 });
song.ornamentKinds   // e.g. { 'upper neighbor': 114, 'turn (upper first)': 92, … }
song.bsn             // BSN2 (see below)
```

```bash
npx beast-sound mainnet 52918 --engine 2 -o warlock-v2.mid
```

A canon at the sixth below and third above, invertible at the octave, ornamented by the V2 engine
(25 ornament kinds) with the Beast's suffix choosing which kinds are allowed. Each Beast's melody is
walked once under the constraints of every possible live state, so kills, level and rank change the
stretto, voices and form but never the melody. Port of `src/composition/beast_engine_v2.cairo`,
checked byte for byte against Cairo renders. Defaults and the findings behind them:
`docs/beasts/engine_v2_defaults.md`. v1 stays the default until the v2 defaults are signed off by
listening.

## Compact format (BSN1 / BSN2)

BSN2 carries engine v2 scores at 10 bits per note: the written notes (key + duration on a 120-tick
grid) plus the articulation rule, which the decoder re-applies exactly. `bsn2ToMidi(song.bsn)`
rebuilds the identical MIDI file (2,068 notes: 2.7 KB, against 17 KB of MIDI).

### BSN1

For storage, indexers or anywhere bytes matter, `song.bsn` is the score in about 7 bits per note
(436 bytes for the largest possible Beast, versus 3.7 KB as MIDI). `bsnToMidi(song.bsn)` rebuilds
the identical MIDI file. Layout is documented in `src/engine.js`.
