Recommendation

Ship Sound beside V3, not inside it

Sound launches as one small, separate Starknet contract that reads Beasts V3. It needs no changes to beasts_nft, the registry, or the token ID layout, so it can't slow the V3 launch. Everything the composer needs already exists onchain:

  • Identity from the 116-bit token ID: species, prefix, suffix, level, health, shiny, animated, tier, type.
  • Kills and rank from the Beasts NFT: get_adventurers_killed, get_beast_rank, get_species_count. These are live Death Mountain reads for species 1–75 and the refresh_stats cache for community species.
  • Scars and glory from Summit: get_live_stats gives revival_count (deaths) and summit_held_seconds.
  • Seed = poseidon('BEAST_SOUND_V1', id, prefix, suffix), the same inputs as the entity hash. A V2 Beast keeps its melody through burn_and_mint, because the seed contains no contract address, chain id or owner.
  • Creator authority = holder of the species' Genesis Beast, the same rule V3 now uses for art.

MVP: a Sound rarity drop across the original 93,225, every Genesis Beast singing, and an opt-in for community species. Creators can use the Koji composer or their own provider.

If a new contract isn't wanted

The whole thing also runs offchain

Sound doesn't have to be a contract at all. @koji/beast-sound composes any Beast's theme from data Provable Games already publishes: the token's traits, the NFT's kills and rank, and Summit's deaths and hours held. Nothing needs to be deployed, stored or changed on their side.

The contract surface

BeastSound: one interface, mirrors IBeastArtProvider

#[starknet::interface]
trait IBeastSound<T> {
    // rarity + opt-in
    fn has_sound(self: @T, token_id: u256) -> bool;
    fn get_sound_provider(self: @T, species_id: u64) -> ContractAddress;   // 0 = Koji default
    fn set_sound_provider(ref self: T, species_id: u64, provider: ContractAddress);
        // caller == beasts_nft.owner_of(genesis_token_id(species_id)) — same rule as V3 art
    fn lock_sound(ref self: T, species_id: u64);                            // one-way, like lock_art

    // canonical state (cheap views)
    fn get_composition_params(self: @T, token_id: u256) -> BeastCompositionParams;
    fn get_music_state_hash(self: @T, token_id: u256) -> felt252;

    // canonical score
    fn get_score_hash(self: @T, token_id: u256) -> felt252;
    fn get_score_notes(self: @T, token_id: u256) -> Array<felt252>;  // BSN1: 7 bits per note
    fn get_score_midi(self: @T, token_id: u256) -> Array<felt252>;   // full MIDI file (7× larger)
}

#[starknet::interface]
trait IBeastSoundProvider<T> {   // Koji canonical class, or a creator's own
    fn get_score(self: @T, beast: PackableBeast, live: BeastV3LiveState) -> Span<felt252>;
}

struct BeastV3LiveState {
    adventurers_killed: u64,   // beasts_nft.get_adventurers_killed
    scars: u64,                // Summit revival_count + (collect count − 1)
    summit_held_seconds: u64,  // Summit summit_held_seconds
    rank: u16,                 // beasts_nft.get_beast_rank (0 = Genesis)
    species_count: u16,        // beasts_nft.get_species_count
}

BSN1 is the client payload. Every note in a Beast score sits on the beat grid, all notes share one duration, voices play runs of consecutive beats, and velocity follows the articulation rule. So the stream is an 81-bit header, 24 bits per run, and 7 bits per note (the MIDI key). The heaviest Beast's 400 notes fit in 436 bytes (17 felts), against 3.7 KB (122 felts) as MIDI. The client's bsnToMidi rebuilds the exact MIDI file, so it still verifies against the score hash.

A custom sound provider that reverts only breaks its own species, as with art. token_uri never calls a sound provider, as with kill stats. Metadata gets at most a pure Sound trait and an animation_url pointing at a player.

The rarity drop

How 93,225 Beasts learn whether they sing

  1. Before V3 mainnet, commit to a salt (for example the hash of a future block), so nobody can pre-compute winners.
  2. Reveal it at launch. has_sound = genesis || poseidon('BEAST_SOUND_DROP', salt, id, prefix, suffix) % 10000 < drop_bps.
  3. The result depends only on (id, prefix, suffix). A V2 holder can check their Beast before they burn_and_mint, and the result carries across. It needs no storage, no migration step and no change to the token ID.

This page uses a demo salt and 5% (500 bps), the same scale as Shiny and Animated. Genesis Beasts always have Sound and act as each species' signature theme.

What mainnet data says

Calibrating the living mapping

  • Kills are sparse. On log₂ buckets, today's Beasts reach at most section C. The form has room to grow as they rack up kills.
  • Death Mountain can't supply scars, but Summit can. Summit deaths drive the scar layer: 7+ deaths invert the follower and drop section C a third. Summit time adds to the Beast's history, and 16+ hours adds ornament density.
  • Level and health vary widely (level 19–207, health 11–1023). They feed voice count (level ≥ 64) and register weight (health ≥ 250 sits a band lower).
  • Species sizes differ (882 to 1,242 minted). Rank tiers are percentiles of the species.

What building engine v2 uncovered

The old invertible canon played one melody for everyone

The original 3-voice invertible canon (offsets 0, −4, +3) leaves almost no legal melodies once invertibility is enforced: a single melody at the tightest stretto, 4–16 at the loosest, across 1,500 seeds. A search over every 3-voice configuration found ones that stay invertible at every stretto with a distinct melody per Beast. Engine v2 uses a canon at the sixth below and third above, and walks each Beast's melody once under every constraint its history could ever impose.
